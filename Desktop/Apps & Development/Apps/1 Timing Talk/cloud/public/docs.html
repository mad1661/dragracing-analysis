API Documentation

Everything you need to stream live timing data into your application.

Quick Start

1. Get an API Key

Go to the Dashboard, create an account, and generate an API key.

2. Find a Track

The track directory is public -- no key needed to browse:

curl https://nhra-timing-api.web.app/api/tracks

3. Stream Data

Use the JavaScript SDK or connect directly via SSE:

<script src="https://nhra-timing-api.web.app/timing-talk.js"></script>
<script>
  const tt = new TimingTalk("tt_your_api_key");

  // Stream live data from a track
  tt.stream("DEVICE_ID", (data) => {
    console.log(data.raw);       // raw serial string
    console.log(data.timestamp); // ISO timestamp
  });
</script>

Authentication

There are two types of authentication depending on the endpoint:

MethodUsed ForHow
PublicTrack directoryNo authentication needed
API KeyStreaming & data accessHeader: X-API-Key: tt_... or query param: ?key=tt_...
AuthKey managementHeader: Authorization: Bearer <token>

Endpoints

Public (No Auth)

GET /api/tracks
List all registered tracks. Supports ?q=name search and ?online=true filter.
GET /api/tracks/:trackId
Get details and live status of a specific track.
GET /api/tracks/live
List only tracks that are currently online.

Requires API Key

GET /api/stream/:deviceId
SSE live data stream. Add ?source=serial or ?source=tcp to filter by channel. Omit for both.
// Stream serial data only
const es = new EventSource(
  "https://nhra-timing-api.web.app/api/stream/DEVICE_ID?key=tt_yourkey&source=serial"
);

// Stream TCP/JSON data only
const es2 = new EventSource(
  "https://nhra-timing-api.web.app/api/stream/DEVICE_ID?key=tt_yourkey&source=tcp"
);

// Stream both (default)
const es3 = new EventSource(
  "https://nhra-timing-api.web.app/api/stream/DEVICE_ID?key=tt_yourkey"
);

es.onmessage = (e) => {
  const data = JSON.parse(e.data);
  console.log(data.source, data.raw); // "serial" or "tcp"
  if (data.parsed) console.log(data.parsed); // structured fields (TCP/JSON only)
};
GET /api/latest/:deviceId
Latest data snapshot. Add ?source=serial or ?source=tcp. Without filter, returns both channels.
# Get both channels
curl -H "X-API-Key: tt_yourkey" \
  https://nhra-timing-api.web.app/api/latest/DEVICE_ID
# Returns: { "data": { "serial": {...}, "tcp": {...} }, ... }

# Get serial only
curl -H "X-API-Key: tt_yourkey" \
  "https://nhra-timing-api.web.app/api/latest/DEVICE_ID?source=serial"
# Returns: { "data": { "raw": "...", ... }, ... }
GET /api/history/:deviceId
Historical readings. Supports ?limit=100 and ?after=ISO_TIMESTAMP for pagination.

Key Management (Firebase Auth)

POST /api/keys
Generate a new API key. Body: { "label": "My Key" }
GET /api/keys
List all your API keys.
DELETE /api/keys/:keyId
Delete an API key.

cURL Examples

# List all tracks
curl https://nhra-timing-api.web.app/api/tracks

# Search tracks by name
curl "https://nhra-timing-api.web.app/api/tracks?q=maple"

# Get latest reading (API key required)
curl -H "X-API-Key: tt_yourkey" \
  https://nhra-timing-api.web.app/api/latest/DEVICE_ID

# Get last 50 readings
curl -H "X-API-Key: tt_yourkey" \
  "https://nhra-timing-api.web.app/api/history/DEVICE_ID?limit=50"

# Stream data via SSE
curl -H "X-API-Key: tt_yourkey" -N \
  https://nhra-timing-api.web.app/api/stream/DEVICE_ID

Data Sources

Each Pi accepts timing data from two inputs simultaneously:

SourceHowFormat
USB SerialPlug a serial timing adapter into any USB portRaw text lines (auto-detected baud rate)
TCP/IPConnect to the Pi on port 4000Newline-delimited JSON or plain text

Both sources feed into the same pipeline: logged locally, synced to cloud, and streamed to API consumers.

TCP/IP JSON Input

When the timing system sends JSON over TCP, the API streams it with both raw and parsed fields:

// Timing system sends over TCP:
{"lane": 1, "et": "7.432", "speed": "186.21", "driver": "John Force"}

// API streams to your app:
{
  "type": "data",
  "raw": "{\"lane\":1,\"et\":\"7.432\",\"speed\":\"186.21\",\"driver\":\"John Force\"}",
  "parsed": {
    "lane": 1,
    "et": "7.432",
    "speed": "186.21",
    "driver": "John Force"
  },
  "source_type": "tcp_json",
  "source_port": "tcp:192.168.1.50:9100",
  "timestamp": 1709123456789
}

Sending Data via TCP

# From any machine on the same network as the Pi:
echo '{"lane":1,"et":"7.432","speed":"186.21"}' | nc PI_IP_ADDRESS 4000

# Or from Python:
import socket, json
s = socket.socket()
s.connect(("PI_IP_ADDRESS", 4000))
s.send(json.dumps({"lane": 1, "et": "7.432"}).encode() + b"\n")
s.close()

Rate Limits & Notes

SSE Streams: One connection per API key per device. Reconnects automatically with the SDK.

Polling: Recommended minimum interval of 2 seconds for /latest.

History: Maximum 1000 records per request.

CORS: All endpoints support cross-origin requests from any domain.
